## 2. 왜 이 프로덕트가 필요한가 (배경 및 문제 정의)

### 2-1. 배경
- 이력서/자소서만으로는 "기획 역량"과 "디자인 실행력"을 동시에 증명하기 어려움
- 노션(Notion)이나 PDF 포트폴리오는 정적이고, 인터랙션·구조화된 탐색 경험을 주기 어려움
- 프로젝트 수가 많아 '양'은 확보했지만, '탐색 효율'과 '차별화된 인상'을 못 주면 오히려 강점이 묻힐 위험

### 2-2. PDF 포트폴리오 vs 웹사이트 포트폴리오 비교

| 비교 항목 | PDF 포트폴리오 | 웹사이트 포트폴리오 |
|---|---|---|
| 탐색 방식 | 순차적(스크롤/페이지 넘김), 선형적 | 필터·링크 기반 비선형 탐색, 원하는 프로젝트로 바로 진입 가능 |
| 인터랙션 | 정적 이미지·텍스트만 가능 | 스크롤 애니메이션, 클릭 인터랙션, 실제 프로토타입 임베드 가능 |
| 업데이트 | 새 버전 만들어 재배포해야 함 (버전 관리 번거로움) | 실시간 수정·배포 가능, 항상 최신 상태 유지 |
| 접근성/공유 | 첨부파일 형태, 용량 제한, 뷰어 환경에 따라 레이아웃 깨질 수 있음 | URL 하나로 공유, 모든 기기·환경에서 동일한 경험 제공 |
| 증명 가능한 역량 | 문서 구성력, 정적 비주얼 디자인 | 문서 구성력 + 정적 비주얼 + **UX/인터랙션 설계력 + 프론트엔드 감각까지 동시 증명** |
| 첫인상/기억도 | 다른 지원자와 형식이 비슷해 차별화 어려움 | 개인 브랜딩(도메인, 커스텀 UI)으로 차별화 가능 |
| 채용담당자 경험 | 다운로드·뷰어 실행이라는 진입장벽 존재 | 링크 클릭 즉시 확인 가능, 진입장벽 낮음 |

> **시사점**: PDF는 '결과물을 정리해서 보여주는 문서'에 가깝고, 웹사이트는 '탐색 경험 자체를 설계하는 프로덕트'입니다. 즉 웹사이트 포트폴리오를 선택하는 순간, **사이트의 UX 자체가 나의 기획·디자인 역량을 증명하는 또 하나의 케이스스터디**가 된다는 차별점이 생깁니다. 이는 앞서 정의한 핵심 가치 제안(5번 항목)과도 직접 연결됩니다.

### 2-3. 해결해야 할 문제 (Problem Statement)
> **"채용담당자가 짧은 시간 안에, 내가 기획과 디자인을 둘 다 잘하는 사람이라는 걸 어떻게 빠르고 확실하게 각인시킬 것인가?"**

세부적으로 풀어야 할 문제:
1. **탐색 문제**: 프로젝트 수가 많아질 때, 방문자가 이탈하지 않고 원하는 프로젝트를 빠르게 찾게 하는 방법
2. **증명 문제**: '기획서를 잘 쓴다'와 '디자인을 잘한다'를 각각, 그리고 동시에 어떻게 증명할 것인가
3. **차별화 문제**: 비슷한 스펙의 지원자들 사이에서 어떻게 기억에 남을 것인가
4. **신뢰 문제**: 인턴/프리랜서 프로젝트는 종종 "완성도가 낮다"는 편견이 있음 → 이를 어떻게 극복할 것인가
5. **전환 문제**: 포트폴리오를 보는 것만으로 채용담당자/실무진이 실제 입사 제안(면접 제안 포함)까지 결정할 수 있을 만큼 확신을 줄 수 있는가 → 단순히 '인상이 좋다'를 넘어, '같이 일해도 되겠다'는 판단 근거(문제해결 과정, 협업 경험, 성과)까지 제공해야 함

## 3. 타겟 사용자 분석

포트폴리오 사이트는 '나'를 위한 게 아니라 **보는 사람**을 위한 프로덕트라는 관점이 핵심입니다. 채용/협업 관점에서 방문자를 세분화합니다.

### 페르소나 A — 실무진 (디자인/기획 팀 리더)
- **목표**: 이 사람이 우리 팀 실무에 바로 투입 가능한가? 사고 과정이 논리적인가?
- **행동 패턴**: 프로젝트 상세페이지까지 깊게 들어가서 리서치·문제정의·의사결정 과정을 꼼꼼히 봄
- **니즈**: 왜 그런 기획/디자인 결정을 내렸는지에 대한 '근거'
- **소요 시간**: 프로젝트 1개당 2~5분 정도 투자 가능

### 페르소나 B — HR/채용담당자
- **목표**: 서류 스크리닝 단계에서 빠르게 적합 여부 판단
- **행동 패턴**: Home(Hero+Selected Works+About 요약)만 훑어보고 판단, 상세페이지·About 페이지는 관심 있을 때만 선택적 진입
- **니즈**: 직관적인 첫인상, 명확한 역할/역량 태그, 빠른 로딩
- **소요 시간**: 전체 사이트에 30초~1분

> **반영 사항**: 02번 기획서에서 Home을 "굵고 짧은 예고편" 구조(Hero→Works→About 요약→CTA)로 슬림화하기로 확정함에 따라, 페르소나 B의 행동 패턴과 정확히 맞아떨어짐을 재확인. 경력·Skills·Process 등 상세 서사는 About 페이지로 위임되어 있어, 이 페르소나는 Home만으로도 핵심 판단 정보(포지셔닝, 대표작, 짧은 자기소개)를 모두 얻을 수 있음. 추가로, 프로젝트 페이지에 실제 **필터 탭**(전체/인턴/외주/회사)이 도입되어, 페르소나 B가 특정 유형(예: 회사 프로젝트만)을 빠르게 선별해 볼 수 있는 탐색 경로도 마련됨 — 1번 탐색 문제(2-3 참고)에 대한 실질적 해결책이 구현된 상태

### 페르소나 C — 프리랜스 클라이언트 (잠재 발주처)
- **목표**: 실제로 프로젝트를 맡길 만한 실행력이 있는가
- **행동 패턴**: 완성도, 결과물의 퀄리티, 커뮤니케이션 문서(기획서 등) 위주로 확인
- **니즈**: 신뢰도, 결과물의 임팩트(성과 지표), 협업 프로세스에 대한 확신

> **인사이트**: 페르소나 A와 B는 상반된 요구를 가짐 (깊이 vs 속도) → 이전 답변에서 제안한 "아카이브는 심플, 상세페이지는 깊게"의 계층 구조가 이 문제를 구조적으로 해결함을 재확인

## 4. 핵심 가치 제안 (Value Proposition)

| 경쟁 대안 | 한계 | 이 프로덕트의 차별점 |
|---|---|---|
| PDF/노션 포트폴리오 | 정적, 탐색 비효율, 인터랙션 부재 | 필터링·스크롤텔링으로 탐색 경험 자체를 디자인 역량의 증거로 활용 |
| 일반 UI 포트폴리오 (비주얼만) | 기획 과정이 안 보임, "예쁘기만 하다"는 인상 | 리서치→기획→디자인 프로세스를 문서 수준으로 노출해 논리력 증명 |
| 텍스트 위주 기획 포트폴리오 | 결과물이 안 보여서 실행력 의심받음 | 기획 문서 + 실제 UI 결과물을 나란히 배치해 '생각을 실체화하는 능력' 증명 |

**핵심 차별화 포인트**: 이 사이트 자체가 "기획+디자인을 통합적으로 잘한다"는 것을 보여주는 **살아있는 포트폴리오 작품**이 되어야 함 (메타적 증명)

### 4-1. 톤앤매너를 통한 차별화 (02번 기획서 갱신 반영)

레퍼런스 벤치마킹 결과, **콘텐츠 구조뿐 아니라 카피의 톤앤매너 자체가 하이브리드 포지셔닝을 뒷받침하는 요소**로 확인됨.

- **굵고 단정적인 헤드라인**("~합니다")으로 확신 있는 인상을 전달해 "기획+디자인을 둘 다 잘한다"는 메시지에 설득력 부여
- **Home = 예고편 / About = 상세 증명**의 역할 분담을 통해, 페르소나 B(빠른 판단)와 페르소나 A(깊은 검증) 양쪽의 상반된 니즈를 카피 레벨에서도 구조적으로 충족
- 과장된 세일즈 어투 대신 **1인칭·사실 기반 서술**을 유지해, 인턴/프리랜서 경력에 대한 신뢰 문제(2-3의 '신뢰 문제')를 완화하는 방향으로 작용

## 5. 레퍼런스 분석 (경쟁/벤치마킹 관점)

### 5-1. 일반적 패턴 (초기 가설)

기획+디자인 하이브리드 포트폴리오에서 흔히 발견되는 패턴과 리스크:

| 패턴 | 장점 | 리스크 |
|---|---|---|
| 케이스스터디 풀버전 노출 | 깊이 있는 증명 가능 | 로딩 느림, 채용담당자 이탈 |
| 비주얼 중심, 텍스트 최소화 | 임팩트 강함, 스캔 쉬움 | 기획력 증명 부족 |
| 노션/피그마 링크로 대체 | 제작 리소스 절감 | 통일된 브랜딩 경험 부재, 전문성 저하 인상 |
| 산업/도메인별 그룹핑 | 특정 직무 지원 시 관련성 강조 쉬움 | 프로젝트 수 적으면 오히려 빈약해 보임 |

### 5-2. 실제 레퍼런스 벤치마킹 결과 (02번 기획서에서 확정)

초기 가설을 바탕으로 실제 포트폴리오 레퍼런스 2건을 검토하여 톤앤매너와 구조를 확정함.

| 레퍼런스 | 특징 | 채택 여부 |
|---|---|---|
| Rony 포트폴리오 | 여백감, 감성적 자기소개, Home 한 페이지에 About·Skills·Process·Testimonial까지 전부 노출 | 부분 채택 → 정보 밀도가 높아 페르소나 B(빠른 스캔)에게는 부담이 될 수 있다고 판단, 콘텐츠 항목만 차용하고 배치는 재조정 |
| Showcasy 포트폴리오 | 굵은 타이포, 확신형 헤드라인, Home은 Hero→Works→About 요약만 간결하게 구성, 상세 서사는 About 페이지로 분리 | **최종 채택** → 5-1(정보구조) 원칙 "아카이브는 심플, 상세는 깊게"와 구조적으로 가장 일치 |

> **최종 결론**: Home은 Showcasy처럼 **짧고 굵은 예고편**으로, About 페이지는 Rony가 다루던 **경력·Skills·Process·Testimonial 등 상세 서사를 전담**하는 이중 구조로 확정. 이는 3번 페르소나 분석(A: 깊이 vs B: 속도)의 상반된 니즈를 그대로 반영한 결과이며, 최초 가설 5-1의 "필터링 가능한 아카이브 + 계층적 상세페이지" 원칙이 Home-About 관계에도 동일하게 적용된 것으로 볼 수 있음

> 다수의 프로젝트를 보유한 우리 케이스에서는 **"필터링 가능한 그리드형 아카이브 + 계층적 상세페이지"** 구조가 리스크를 가장 잘 상쇄하는 방향으로 판단됨

### 5-3. 상세페이지 구조 실증 분석 (신규 — 클라이언트 11개 전체 확인)

02번 기획서에서 실제 완성된 프로젝트 상세페이지 11개를 전부 분석한 결과, 당초 5-2에서 예측했던 "계층적 상세페이지"가 **단순 반복이 아니라 프로젝트 성격에 따라 스스로 형태를 바꾸는 "가변 템플릿"**으로 구현되어 있음을 확인.

- 7개 공통 대섹션(Hero·기획배경·기획방향·IA·주요화면·Comparison·디자인시스템)은 유지하되, 신규구축/리디자인 여부에 따라 Comparison 섹션 포맷이 달라지고(Before-After vs UX개선포인트), 웹전용/웹+모바일 여부에 따라 주요화면 그룹 수가 달라지며, 리서치 비중이 큰 프로젝트(지티엑스)는 섹션 자체가 추가됨
- **시사점**: 이는 4번의 "메타적 증명" 가치제안을 상세페이지 설계 방식 자체로도 뒷받침함 — 똑같은 템플릿을 기계적으로 반복하지 않고 프로젝트 맥락에 맞게 유연하게 대응한다는 것 자체가 "기획력"의 증거가 됨
- 세부 내용은 `06_프로젝트상세페이지_워딩.md` 참고

## 7. 제약사항 및 고려사항

- **콘텐츠 제약 (갱신)**: 당초 인턴/사내 프로젝트의 NDA 마스킹을 우려했으나, 실제로는 **실명 클라이언트를 그대로 노출**하는 방향으로 확정됨. 대신 상세페이지 서술은 "핵심 과정만 요약적으로, 민감 정보는 제외"하는 수준으로 톤을 조절해 신뢰 문제(2-3)와 NDA 리스크를 동시에 관리
- **리소스 제약**: 1인 제작 → 인터랙션 요소는 임팩트 대비 개발 비용이 큰 항목 위주로 선별 적용 필요
- **유지보수**: 신규 프로젝트가 추가될 때마다 확장 가능한 구조(템플릿화) 설계 필요 — 실제로 12개 프로젝트가 필터 탭 기반의 동일 템플릿 카드로 확장 가능하게 설계됨
- **성과 지표 부재 리스크**: 인턴/프리랜서 프로젝트 특성상 정량 성과(전환율, 매출 등)를 확보 못한 프로젝트가 있을 수 있음 → 정량 지표가 없으면 정성적 임팩트(사용자 피드백, 팀 채택 여부 등)로 대체하는 기준 필요
- **정보 밀도 제약**: Home을 예고편 구조로 확정함에 따라, Home에는 About/Skills/Process 등 상세 콘텐츠를 다시 욱여넣지 않도록 주의 필요 → 신규 섹션 추가 요청이 생기더라도 우선 About 페이지 확장을 검토
- **다크모드 보류 (신규)**: 개발 중 이슈가 발생하여 다크모드는 당분간 범위에서 제외. Header 우측 아이콘 디자인은 재확정 필요 (02·03번 문서 오픈 이슈 참고)
- **자기참조 프로젝트의 정체성 (신규)**: "AXION" 자체를 프로젝트로 소개하는 카드가 추가되었는데, 이는 프로덕트 4번의 "메타적 증명" 가치 제안과 정확히 맞닿아 있는 흥미로운 설계임. 다만 인턴/외주/회사 3개 필터 어디에도 속하지 않아 필터 UX상 예외 케이스로 남아있어 정리가 필요함 (02·03번 오픈 이슈 참고)
- **상세페이지 세부 문구 미확정 (신규)**: 11개 상세페이지의 대분류 구조는 확인됐지만, 문제정의 불릿·기획방향 카드 문구·IA 표 세부 행 등은 이미지 해상도 한계로 "재확인 필요" 상태로 남은 항목이 많음 (`06_프로젝트상세페이지_워딩.md` 참고) — 개발 착수 전 실제 콘텐츠 원본 확보 권장
