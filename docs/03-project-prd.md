## 2. 목표 (Goals) / 목표가 아닌 것 (Non-Goals)

### Goals
- HR/채용담당자가 메인페이지만으로 30초~1분 내 핵심 역량을 파악할 수 있다
- 실무진이 소개페이지에서 업무 프로세스(5 Step)를 통해 사고 논리를 검증할 수 있다
- 프로젝트 페이지에서 필터 탭(전체/인턴/외주/회사)으로 12개 프로젝트를 빠르게 탐색할 수 있다
- 어느 페이지에 있든 Big CTA를 통해 즉시 연락(이메일/전화)할 수 있다

### Non-Goals (이번 범위 제외)
- 회원가입/로그인 기능
- 댓글, 방명록 등 커뮤니티 기능
- 다국어(영/한) 지원 — 추후 확장 검토
- CMS 백오피스 (콘텐츠는 코드 레벨 또는 정적 파일로 관리)
- 뉴스레터 구독 폼 (메뉴 패널 하단 영역은 미적용 확정)

## 3. 사용자 스토리 (User Stories)

| ID | As a (역할) | I want to (요구) | So that (목적) |
|---|---|---|---|
| US-01 | HR 담당자 | 메인페이지 진입 시 3초 안에 무슨 역량을 가진 사람인지 알고 싶다 | 스크리닝 시간을 줄이기 위해 |

## 7. 데이터 구조 (콘텐츠 모델 — 실제 카드 구성 기준 갱신)

### 7-1. Project (프로젝트 카드/상세 공용)
```
Project {
  id
  title                // 예: "머니가드서비스(주)"
  category             // 예: "WEB Design", "WEB Dashboard Design"
  tag                  // 카드 상단 단일 키워드 태그, 예: "핀테크", "금융", "블록체인"
  summary              // 한 줄 설명
  labels[]             // 하단 라벨 칩, 예: ["인턴 프로젝트", "B2B", "UX/UI 디자인", "WEB"]
  filter_type          // 필터 탭 매칭용: "인턴" | "외주" | "회사" | null(AXION처럼 미소속)
  thumbnail_image
  featured             // 메인페이지 미리보기 4개 노출 여부 (boolean)
  order                // 프로젝트 페이지 내 노출 순서
  detail_content {     // 상세페이지 콘텐츠 (클라이언트 11개 전체 분석 기준, 가변 템플릿 구조)
    project_type         // "신규구축" | "리디자인" — comparison 포맷 분기용
    scope_type           // "WEB" | "WEB+Mobile" | "WEB+Tablet+Mobile" — key_screens 그룹 수 분기용
    hero_meta {
      period            // 예: "2024/10 - 2024/12"
      role_breakdown[]  // 예: ["WEB 서비스 기획 (50%)", "UX/UI 디자인 (100%)"]
      tools[]           // 예: ["Figma"]
      deliverables[]    // 예: ["UX/UI 디자인(1/2안)", "콘텐츠 라이팅(가안)"]
    }
    background_overview {
      problem_definition[]     // 불릿 리스트
      key_tasks[]               // 불릿 리스트 ("핵심 과제")
      project_goals[]           // 불릿 리스트
      client_requirements[]     // 불릿 리스트
    }
    strategy {
      label_variant       // "Strategy/기획방향 정의" | "Direction/디자인 방향 정의" — 프로젝트별 확정 라벨 (화면 기준 그대로)
      description
      direction_cards[]  // 4개, 각 {title, description}
    }
    research_deep_dive {  // 조건부 (지티엑스 등 리서치 비중 큰 프로젝트만 존재, nullable)
      problem_analysis[]
      client_interview_quotes[]
      user_persona_table[]
      permission_table[]
    }
    structure_ia {
      description
      ia_table[]  // {depth1, depth2, depth3_url}
    }
    key_screens {
      description
      groups[] {          // scope_type에 따라 1~3개: "WEB View Design" / "Mobile View Design" / "Tablet View Design"
        group_title
        page_types[] {     // 예: "랜딩 페이지"
          type_title
          images[]         // 통상 2장
        }
      }
    }
    comparison {
      format              // "before_after" | "improvement_points" — project_type에 따라 결정
      description
      before_image         // format=before_after일 때만
      after_image
      before_points[]
      after_points[]
      improvement_points[] // format=improvement_points일 때만, {number, title}
    }
    design_system {
      logo_image
      logo_concept_text
      typography {
        font_families[]     // 프로젝트마다 1~3개, 예: ["Pretendard"] 또는 ["Inter","Pretendard","SF Pro"]
        heading_scale[]    // Heading 1~6, 각 {level, size, weight}
      }
      grid {
        basis               // "Desktop" | "Mobile" — 프로젝트 성격에 따라 분기
        width                // 예: "1920px" 또는 "375px"
        columns, gutter, margin
      }
      colors {
        primary[]    // {name, hex}
        neutral[]    // {name, hex}
        semantic[]   // {name, hex, usage}
      }
    }
  }
}
```

> 참고: AXION 자기참조 프로젝트는 실제 리스트에서 제거된 것으로 최종 확인됨 — `filter_type` null 케이스는 더 이상 발생하지 않음 (v0.9 기준 데이터 모델에서 제거 검토 대상)

```
ProcessStep {
  step_number     // 01~05
  label_kr        // 예: "문제 정의"
  label_en        // 예: "Problem Discovery"
  headline        // 예: "사용자와 비즈니스의 문제를 발견합니다"
  details[]       // 세부 설명 3개 배열
}
```

> 이 구조를 기준으로 데이터를 미리 정리해두면, 실제 개발 단계에서 콘텐츠를 바로 넣을 수 있어 작업 속도가 빨라집니다.
