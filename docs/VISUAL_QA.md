# 프로젝트 상세 페이지 시각 검증

Figma 기준 이미지와 8개 프로젝트 상세 페이지를 동일한 1200px viewport에서 캡처해 비교합니다. 픽셀 차이는 보조 지표이며, 섹션 누락·페이지 높이·콘솔 오류·에셋 실패·가로 넘침을 함께 검사합니다.

## 실행

```bash
# 전체 8개 페이지
npm run visual:project-details

# 특정 페이지
npm run visual:project-details -- --project vazoom

# 다른 서버 사용
npm run visual:project-details -- --base-url http://127.0.0.1:3100
```

서버가 없으면 `npm run dev`로 한 번 실행하고, 이미 정상 서버가 있으면 재사용합니다. 캡처가 끝나면 도구가 시작한 서버만 종료합니다.

## 결과 위치

- Figma 기준: `tests/visual/figma-baselines`
- 최신 실제 캡처·diff·요약: `tests/visual/results/latest`
- 실행별 보존 결과: `tests/visual/results/<timestamp>`
- 매핑 설정: `tests/visual/project-details.config.mjs`

상태는 다음처럼 해석합니다.

- `passed`: 런타임·콘솔·에셋·필수 섹션 오류가 없고 시각 차이가 허용 범위 안입니다.
- `review`: 기능 오류는 없지만 높이 또는 픽셀 차이가 있어 섹션별 실제 화면 확인이 필요합니다.
- `failed`: 런타임·콘솔·에셋·필수 섹션 오류, 가로 넘침 또는 큰 구조 차이가 있습니다. 명령도 실패 코드로 종료합니다.

`critical`은 런타임 오류, 콘솔 오류, 깨진 에셋 또는 필수 섹션 누락입니다. `high`와 `medium`은 페이지 높이와 픽셀 차이 기반의 우선 검토 신호입니다. 폰트 안티앨리어싱만 다른 경우에는 diff 이미지에서 작은 글자 윤곽만 붉게 표시됩니다.

## 자동 보정 운영 절차

1. 전체 리포트에서 공통 `failed` 원인을 먼저 확인합니다.
2. DOM·데이터·에셋·폰트 상태를 확인하고 원인이 공통 컴포넌트인지 페이지별 데이터인지 분리합니다.
3. 공통 수정은 1회, 페이지별 수정은 최대 2회만 수행합니다.
4. 수정마다 정적 검사 후 동일 viewport로 재캡처합니다.
5. `latest/summary.md`와 개별 `*-diff.png`를 기준으로 치명적·높음 차이가 사라졌는지 확인합니다.
6. 최종적으로 `npm run qa`와 비대상 대표 페이지를 검증합니다.

이 스크립트는 검증과 실패 감지를 자동화합니다. CI에서 임의로 소스 코드를 변경하지 않으며, 보정은 원인을 확인한 Codex 작업에서 최소 범위로 수행합니다.

## Figma 기준 갱신

1. Figma MCP 읽기 기능으로 정확한 프레임 node ID의 디자인 컨텍스트와 스크린샷을 각각 한 번 가져옵니다.
2. 1배율 PNG를 `tests/visual/figma-baselines/<slug>.png`로 저장합니다.
3. 프레임 크기 또는 node ID가 바뀌었으면 설정 파일도 함께 갱신합니다.
4. 전체 검증을 실행해 기준 변경의 영향을 확인합니다.

Figma 파일은 이 과정에서 수정하지 않습니다. 동일 실행 중 같은 기준을 반복 조회하지 않습니다.

기준 이미지는 자동 덮어쓰기하지 않습니다. Figma 변경이 승인된 경우에만 기존 PNG를 별도 보관한 뒤 교체하고, node ID·프레임 크기·변경 사유를 함께 검토합니다.

## 새 프로젝트 추가

1. 라우터와 프로젝트 데이터에서 slug와 URL을 확인합니다.
2. Figma frame node ID와 1200px 기준 높이를 확인합니다.
3. 기준 PNG와 정확한 에셋을 저장합니다.
4. 설정의 `expectedSections`와 구현 파일을 등록합니다.
5. 특정 페이지 검증 후 전체 검증으로 공통 컴포넌트 회귀를 확인합니다.

## 페이지별 매핑과 판정 근거

`tests/visual/project-details.config.mjs`에 프로젝트명, Figma 프레임명·node ID, 로컬 URL, viewport, 구현 파일, 기준 이미지, 필수 섹션을 한 곳에서 관리합니다. 프로젝트명만으로 추측하지 않고 slug·라우터·카드 링크·데이터·에셋 경로를 함께 확인합니다.

픽셀 diff는 페이지 높이가 긴 특성상 단독 합격 기준으로 사용하지 않습니다. 다음 순서로 판정합니다.

1. HTTP·런타임·콘솔·에셋·필수 섹션
2. 가로 넘침과 전체 높이 차이
3. 컨테이너·섹션 순서·이미지 비율·핵심 타이포그래피
4. 간격·색상·테두리·radius·그림자
5. 브라우저별 글꼴 안티앨리어싱
